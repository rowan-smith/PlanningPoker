# Core — domain rules

This directory owns teams, sessions, tickets, scoring decks, participation, votes and state transitions.

- Write framework-independent, testable domain logic.
- Do not import UI, HTTP, database, Jira or other vendor libraries.
- Represent external systems through stable interfaces or neutral domain types, not vendor DTOs.
- Treat voters, observers, invited members and skipped members as distinct participation states where needed.
- Determine completion from eligible voters for the relevant ticket, not total attendees.
- Preserve vote secrecy; never return identity-to-choice pairs in public results.
- Handle simultaneous submissions and state changes deterministically; leave transactional enforcement to the application/persistence boundary.
- Make the selected final estimate distinct from raw votes and moderator overrides.
- Test edge cases before widening the API.

Domain functions are pure: they take state and `now`, return new state, and throw `DomainError`. IDs are generated by the caller.

See `docs/PRODUCT_RULES.md` for confirmed behaviour and open decisions.
